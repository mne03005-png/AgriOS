# AgriOS V1.0 产品范围

> 基线：2026-08-06；本文件定义目标，不代表功能已经完成。

## 唯一定位与首个场景

AgriOS V1.0 是面向中国家庭农场、种植大户和合作社的“农业现场管理与智能灌溉操作系统”。首个验收场景是 300 亩洋葱地，先以一个 Zone 完成土壤湿度、天气、太阳能、泵阀、水位/流量和用水监测，以及安全的人工/辅助灌溉闭环，再扩展到全场。

## 目标用户与五类角色

| 目标角色 | 主要终端 | V1 职责 |
|---|---|---|
| FARMER | 手机优先 | 看现场、记农事、执行经授权的人工灌溉、处理告警 |
| MANAGER | 手机/平板/电脑 | 计划、审批、成本、生产档案和报表 |
| INSTALLER | 手机/平板/电脑 | 建场、绑定、检查、验收和交付记录 |
| ENGINEER | 电脑为主，手机/平板现场调试 | 配置、诊断、趋势、Edge/PLC 联调 |
| SUPER_ADMIN | 电脑完整管理，手机应急 | 租户、权限、审计、平台配置和紧急只读/停机管理 |

现有 Prisma `UserRole` 有 13 个枚举（含 `FARMER/INSTALLER/PLATFORM_ADMIN/TENANT_ADMIN` 等），与上述五类产品角色尚未一一收敛；V1 应通过明确映射表和权限矩阵兼容迁移，不直接删除历史枚举。

## 终端边界

- 手机：农户日常、现场检查、告警确认、审批、人工操作；危险操作必须二次确认并显示设备/Zone/影响。
- 平板：地图、批量现场部署、巡检和管理看板。
- 电脑：工程配置、全量管理、报表、审计、拓扑和批量维护。
- V1 使用一套 Vue 3/Vite 响应式产品；当前 `apps/mobile` 是候选代码基线，但须改名/重新定义为统一前端后才能称为多终端正式产品。

## V1 做什么

- 统一认证、租户、五类角色、权限和审计。
- 农场、地块、Zone、作物季、农事记录、成本和生产档案。
- 一个 Zone 的设备建档、安装验收、遥测、告警和历史。
- 手动灌溉与带人工批准的辅助灌溉；自动灌溉仅在硬件台架及现场验收后开放。
- PLC 硬安全、Edge 离线缓存/补传/命令去重、云端审批与追溯。
- 手机、平板、电脑统一访问；生产环境失败必须 fail closed，不得透明显示 Mock。
- QGIS/QField 数据交换；ThingsBoard 仅作为工程诊断；Grafana 仅作工程趋势。

## V1 不做什么

农资电商、支付、全国平台、政府大屏、区块链、农机自动驾驶、复杂无人机 AI 识别，以及任何无真实数据的展示模块均停止。AI 不得绕过 Safety/PLC 控制泵阀。farmOS 不成为第二主系统；WebODM 延后至 V1.1，ChirpStack 延后至 V1.2；Hiveeyes、AquaCrop、AgOpenGPS 仅保留规划研究。

## 完成定义

“完成”必须同时满足：正式入口可用；真实 API 和持久化数据可追溯；租户/权限/审计测试通过；生产禁用 Mock；设备命令有唯一 ID、批准、幂等、ACK、超时和失败状态；PLC/硬接线保护通过；Edge 断网/补传通过；一个真实 Zone 连续运行 7 天、30 天并形成签字验收；备份恢复、回滚、监控和运维手册演练通过。页面存在、HTTP 200、容器健康、模拟器通过或文档存在，均不单独构成完成。
