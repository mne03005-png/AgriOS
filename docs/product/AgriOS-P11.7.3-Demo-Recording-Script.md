# AgriOS Mobile：农业版特斯拉中控屏 Demo

## 录屏定位

这支 Demo 展示 AgriOS 如何把 IoT、GIS、灌溉、水肥、无人机、成本、病虫害和产量因素放进一个农业移动中控屏。

建议访问：

```text
/showcase
```

按页面顺序录制，每页讲解 20-40 秒。

## 1. Demo Status

打开 `/demo-status`，确认所有模块 ready。

讲解词：

> 这是 AgriOS 的 Demo 健康检查。我们不是只做一个静态页面，而是检查真实后端数据链路：农场、地块、设备、遥测、灌溉设计、轮灌、水肥、无人机、成本、作物健康、产量因素和农事动态。所有模块 ready 后，移动端就可以进入演示。

## 2. Cockpit

打开 `/cockpit`。

讲解词：

> 这是 AgriOS Mobile 的农场驾驶舱。它像农业版特斯拉中控屏，把今日风险、设备在线率、今日用水、无人机作业、轮灌状态、水肥状态和农事动态集中在一个屏幕里。管理者不用在多个系统之间切换。

## 3. Map

打开 `/map`。

讲解词：

> 地图页展示地块边界、设备点位、无人机航线和覆盖图层。即使没有真实地图 SDK，系统也提供驾驶舱式 SVG mock map，保证演示和离线环境不白屏。后续接入高德、百度或 Google 地图时，业务数据结构保持一致。

## 4. Operations

打开 `/operations`。

讲解词：

> 作业页把轮灌、水肥、泵站、无人机等作业统一展示。P11 阶段仍然坚持安全策略：系统可以记录和建议，但不会默认自动开泵、开阀或控制无人机。

## 5. Drone Operations

打开 `/drone-operations`。

讲解词：

> 无人机作业页展示大疆 KML、GeoJSON、CSV 导入后的结果。系统会解析航线、覆盖区、面积、覆盖率、漏喷和重喷等指标，并生成地图图层和业务记录。

## 6. Drone Review

打开 `/drone-reviews`。

讲解词：

> 无人机导入结果不会直接进入正式业务链路，而是先进入审核台。人工可以确认地块、绑定边界、核查覆盖区，再批准进入报告、成本、作物健康和产量因素。

## 7. Reports

打开 `/reports`。

讲解词：

> 报表页面汇总今日灌溉执行情况、无人机喷洒覆盖情况、成本投入、病虫害观察和产量影响因素。这是把生产过程数据转成管理决策数据的关键页面。

## 8. Field Detail

打开 `/fields/demo-field-onion-a`。

讲解词：

> 单地块详情展示了洋葱 A 区的全生命周期数据：作物、土壤、面积、湿度趋势、灌溉设计、轮灌、水肥、无人机作业、成本、健康观察和产量因素。AgriOS 的目标是让每块地都有自己的数字档案。

## 9. 总结

讲解词：

> AgriOS 把 IoT、GIS、灌溉、水肥、无人机、成本、病虫害和产量数据放进一个农业中控屏。它不是单点工具，而是县域农业数字化平台的业务底座。

## 录屏注意

- 先执行 `npx prisma db seed`
- 先访问 `/demo-status`
- 如果页面提示空数据，回到后端执行 seed 并重启服务
- 本 Demo 不自动开泵/开阀
- 本 Demo 不控制无人机
- 本 Demo 不接真实 DJI SDK
