# AgriOS P3 业务留痕设计

## 目标

P3 让 AgriOS 从“能记录数据”进一步变成“能追溯业务过程”。重点是灌溉建议、操作日志、自动成本和地块时间线。

## 灌溉建议

MQTT 上报土壤湿度后，系统会评估灌溉规则：

- 小于 35：建议灌溉。
- 35 到 60：状态正常。
- 大于 60：建议停止灌溉。

如果结果是 `SHOULD_IRRIGATE` 或 `STOP_IRRIGATION`，系统写入 `IrrigationAdvice`。

P3 不自动开泵。原因是农业现场存在水泵空转、阀门状态不一致、管路破损、人工正在作业等风险。系统先给建议，由人确认后再执行，更适合第一阶段样板田。

## 操作日志

`OperationLog` 用于记录关键业务动作：

- 创建地块
- 创建种植季
- 添加农资
- 添加农事记录
- 下发设备指令
- 确认或忽略灌溉建议

这些记录后续可用于审计、复盘、问题排查和农事过程追溯。

## 自动成本

P3 只做创建时自动成本：

- 创建农资记录时，如果 `totalPrice > 0`，自动生成 `CostRecord`。
- 创建农事记录时，如果 `cost > 0`，自动生成 `CostRecord`。

暂不处理更新同步。原因是成本属于账务类数据，后续应设计审核、冲正或重算机制，避免直接覆盖历史记录。

## 地块时间线

地块时间线接口聚合以下事件：

- 种植季创建
- 农资记录
- 农事记录
- 最近传感器数据
- 灌溉记录
- 灌溉建议
- 操作日志

用途：

- 快速复盘一块地最近发生了什么。
- 给农户、合作社管理员查看完整过程。
- 后续为小程序、Web Admin 和溯源档案提供统一数据源。
