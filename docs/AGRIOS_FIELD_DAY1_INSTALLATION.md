## Day0：设备准备

目标：所有设备在工作台完成身份、固件和功能预检，现场不临时烧录未知固件。

### 作业

- [ ] 按 BOM 点货，核对电压、频段、IP 等级、序列号、合格证和备件。
- [ ] 为设备生成 Device Key，贴二维码和人可读标签；建立序列号映射。
- [ ] 烧录发布固件，记录版本和哈希；确认默认泵 OFF、阀 CLOSED。
- [ ] 在 AgriOS 创建 Tenant/Farm/Field/Zone A–D，注册全部 Device 和 Sensor 通道。
- [ ] 一次性凭据写入安全存储；临时文件和照片不得包含密码。
- [ ] 在台架验证 MQTT v1 telemetry/commands/ack、时间同步、sequence、messageId 和离线缓存。
- [ ] 模拟断电重启，确认不会自动启动泵；模拟过期命令必须拒绝。
- [ ] 给 LiFePO4 电池充至 60–80% 运输电量，确认 BMS 与极性。

### Day0 放行条件

设备台账完整率 100%；每台设备至少一条成功 telemetry；控制器在未接负载时完成 ACK；无共享 MQTT 密码；施工图和端子号与实物一致。

## Day1：现场安装

目标：完成机械、水力、电气、通信和平台安装，保持 MANUAL 模式。

### 上午：放线与机械安装

1. 召开安全交底，确认地下管线、水源、排水、急救和断能点。
2. 以西南角为原点放出 20×12 m 边界、四个 Zone、传感器点、阀盒、CP、PV 和 GW。
3. 记录偏差形成红线图；偏差超过 0.5 m 或影响排水/RF 时由负责人批准。
4. 安装水箱、过滤器、泵、止回阀、压力表、流量计、分水器和四阀。
5. 水路加压查漏；排气后记录静压和压降。

### 下午：电气与通信安装

1. 安装 PV、MPPT、电池、DC 保护和控制箱；动力回路保持断开。
2. 持证电工完成极性、绝缘、PE、保险、急停、低液位和过流回路。
3. 安装 GW 和天线，完成以太网/4G 回传；记录每个节点 RSSI/SNR。
4. 埋设土壤探头，安装温湿度防辐射罩、光照和雨量计。
5. 逐设备上线，在平台核对 Zone、battery、RSSI、lastSeen 和固件版本。
6. 创建 Field Pilot，名称包含现场和日期；状态应为 ACTIVE。

### Day1 证据

红线图、全景和关键节点照片、线缆/端子照片、水压记录、电气测量、RF 表、设备在线截图。泵不做无人值守自动运行。

## Day2：传感器校准与数据稳定性

目标：传感器读数可解释，连续数据满足 Field Pilot 计算。

- [ ] 土壤水分按现场土样完成至少两点校准，记录原始值、参考值和系数。
- [ ] 空气温湿度与参考仪并置 30 分钟；光照执行遮光/开阔响应测试；雨量计做定量注水测试。
- [ ] 流量计用容积法核对，压力变送器与机械表对比。
- [ ] 检查 24 小时 sequence、messageId、时间戳、字段完整性和 5 分钟心跳桶。
- [ ] 运行 Field Pilot diagnostics，处理 SENSOR_STUCK、OUT_OF_RANGE、WEAK_SIGNAL。

通过：关键传感器误差在规格内；数据完整率和 MQTT 成功率均 ≥98%；无未解释卡值。

## Day3：首次自动灌溉

目标：从手动带水验证过渡到单 Zone 自动任务。

1. 现场人员检查阀位、水箱液位、过滤器、压力表和急停。
2. MANUAL 模式依次开关 V-A…V-D，每次确认实际动作、反馈和漏水。
3. MANUAL 模式点动泵 5–10 秒，确认流量、压力、电流和无异常振动。
4. 仅选择 Zone A，将泵/阀切到 AUTOMATIC；其他 Zone 保持 MANUAL/CLOSED。
5. 创建 10 分钟以内任务，现场全程值守；记录命令、ACK、流量和土壤响应。
6. 验证正常停泵后阀关闭；随后恢复 MANUAL，复核日报。

立即紧停：流量为零、压力越界、泵异响、线缆发热、阀未到位、平台状态与现场不一致。

## Day4：断网测试

目标：验证断网期间安全、缓存和恢复，不测试“云端仍能控制断网设备”。

1. MANUAL 模式，泵停止、阀关闭，现场两人在场。
2. 记录断网前 sequence 和缓存长度；断开 Edge 上行 30 分钟，不断开节点本地网络。
3. 确认本地采集继续、缓存增长、硬联锁有效；发送的云命令应过期且不得恢复后执行。
4. 恢复主网络，确认 MQTT 自动重连和限速补传；切换备用运营商再重复短测。
5. 核对 OFFLINE/ONLINE、数据去重、sequence 缺口和 MTTR。

通过：补传无业务重复，恢复 ≤10 分钟，无过期命令执行，无泵阀误动作。

## Day5：异常与恢复

目标：证明故障会被发现、设备进入安全态、人工修复后有恢复记录。

- [ ] 模拟 20%/10% 电量，确认 WARNING/CRITICAL 与非安全动作限制。
- [ ] 拔开一个传感器，确认通信/传感器诊断；恢复后状态转 RESOLVED。
- [ ] 模拟阀未到位，泵启动应被拒绝或安全停机。
- [ ] 按下平台紧停和硬急停，确认泵停止、任务失败、SAFETY_STOP 事件。
- [ ] 仅 OWNER/ADMIN 在现场确认后复位紧停锁存。

每项填写故障开始、发现、响应、恢复时间和责任人，不允许为了提高 Health Score 删除异常。

## Day6：数据分析与运行优化

目标：用真实数据判断安装质量，而不是调整评分掩盖问题。

1. 导出/查看 Day1–Day5 日报：土壤首末值、变化、灌溉次数、实测用水、设备状态、异常。
2. 对比四个 Zone 的土壤响应、位置偏差、流量和异常分布。
3. 分析在线率、MQTT 成功率、完整率、灌溉成功率和 MTTR。
4. 只允许调整传感器安装、天线位置、上报周期和经过农艺师批准的阈值；修改需记录前后版本。
5. 重新运行诊断，关闭已验证恢复的工单。

## Day7：综合验收

1. 完成 `AGRIOS_GARDEN_ACCEPTANCE_CHECKLIST.md` 全表。
2. 生成最终日报和 Health Score，冻结测试时间窗。
3. 核对所有 Device、凭据轮换记录、照片、红线图、校准、电气和事件证据。
4. 对 OPEN/CRITICAL 诊断逐项决定：修复后复测或判定失败，禁止带病签字。
5. 四方签字：施工、电气/水利、农艺、平台。

判定：

- 通过：Health Score ≥90，在线 ≥99%，MQTT/完整率 ≥98%，灌溉成功率 ≥99.5%，关键安全事故 0。
- 条件通过：无安全失败，但稳定性门槛不足；保持单 Zone，延长试运行。
- 失败：出现安全联锁失效、非预期启动、无法人工接管或关键数据不可追溯；系统回到 MANUAL 并整改。

## 3. 每日收工要求

泵停止、阀处于设计安全位、工具清点、箱门锁闭、临时线拆除、异常已登记、照片已归档、次日风险已交接。任何人不得把 MQTT 凭据、JWT 或 Wi-Fi 密码发到普通工作群。
